# ОКУЛЯР — деплой на Render

## Что внутри
- `app.py` — Flask-бэкенд: логин, роли, защищённые эндпоинты
- `templates/index.html` — фронтенд, обращается к бэкенду по `/api/...`
- `generate_admin_hash.py` — одноразовый локальный скрипт для получения bcrypt-хеша пароля
- `requirements.txt`, `Procfile` — для деплоя

## Модель защиты (коротко)
- Пароль администратора нигде не хранится в открытом виде — только его bcrypt-хеш,
  в переменной окружения `ADMIN_PASSWORD_HASH`.
- После входа сервер выдаёт подписанный JWT в **httpOnly + Secure + SameSite=Strict**
  cookie. JS на странице этот токен вообще не видит — значит его нельзя украсть через
  уязвимость на фронтенде (XSS) и нельзя подделать без секретного ключа `JWT_SECRET`.
- Каждый admin-запрос (сохранить/сбросить калибровку) сервер проверяет заново по
  cookie — скрытие кнопок в интерфейсе это просто UX, реальное решение принимает сервер.
- Вход администратора ограничен 5 попытками в минуту (`Flask-Limiter`), чтобы
  затруднить подбор пароля.

## Шаг 1 — сгенерировать хеш пароля (локально, у себя на компьютере)
```bash
pip install bcrypt
python generate_admin_hash.py
```
Введёте пароль, получите строку вида:
```
ADMIN_PASSWORD_HASH=$2b$12$...........................
```
Сохраните её — понадобится на шаге 3. Сам пароль в открытом виде никуда сохранять не нужно.

Там же сгенерируйте секрет для подписи токенов:
```bash
python -c "import secrets; print(secrets.token_hex(32))"
```
Это будет значение `JWT_SECRET`.

## Шаг 2 — выложить код в свой репозиторий
Загрузите содержимое этой папки в GitHub/GitLab-репозиторий (Render разворачивает из репозитория).

## Шаг 3 — создать сервис на Render
1. render.com → **New → Web Service** → подключить репозиторий.
2. Runtime: **Python 3**.
3. Build command: `pip install -r requirements.txt`
4. Start command: `gunicorn app:app`
5. В разделе **Environment** добавить переменные:
   - `JWT_SECRET` = (строка с шага 1)
   - `ADMIN_PASSWORD_HASH` = (строка с шага 1, целиком, включая `$2b$12$...`)
   - `COOKIE_SECURE` = `true`
6. Deploy. Render сам выдаёт HTTPS-адрес вида `https://ваш-сервис.onrender.com` —
   это обязательно, `Secure`-cookie без HTTPS браузер не примет.

## Локальная проверка перед деплоем
```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
export JWT_SECRET=dev-secret
export ADMIN_PASSWORD_HASH='(строка с шага 1)'
export COOKIE_SECURE=false   # т.к. localhost без https
flask --app app run
```
Откройте `http://127.0.0.1:5000`. Камера в браузере на `http://localhost` обычно
разрешается без HTTPS — на проде (Render) HTTPS будет уже по умолчанию.

## Если понадобится Fly.io вместо Render
Тот же `Procfile`/`requirements.txt` подходят — просто `fly launch`, а переменные
окружения задаются командой `fly secrets set JWT_SECRET=... ADMIN_PASSWORD_HASH=...`.
Vercel для этого проекта не подойдёт напрямую: у Flask с in-memory хранилищем
калибровки и cookie-сессиями плохо сочетается serverless-модель Vercel
(каждый запрос может попасть на новый "холодный" инстанс). Render/Fly держат
процесс живым между запросами — там всё работает как задумано.

## Дневник фото и сравнение лица
- «Сделать фото на сегодня» сохраняет кадр с камеры на сервере, привязанный к
  сегодняшней дате (повторная съёмка в тот же день перезаписывает фото за эту дату).
- «Сравнить» берёт две выбранные даты, находит лицо на каждом фото (OpenCV),
  выравнивает и считает структурное сходство (SSIM). В ответ — процент схожести
  и тепловая карта отличий (тёплые цвета = сильнее изменилось).
- Это не идентификация "кто на фото", а сравнение одного и того же лица день ко
  дню — специально выбран лёгкий метод (без тяжёлых DL-моделей), чтобы нормально
  собиралось на Render/Fly без долгой сборки и лишней памяти.
- **Важно про хранение:** фото лежат в SQLite-файле (`data/oculus.db`). На Render
  без подключённого persistent disk файловая система контейнера пересоздаётся при
  каждом деплое/перезапуске — фото пропадут. Чтобы данные жили между днями:
  Render → ваш сервис → **Disks** → добавить диск, смонтировать в `/opt/render/project/src/data`,
  и выставить переменную окружения `DATA_DIR=/opt/render/project/src/data`.
  На Fly.io аналогично — `fly volumes create` + примонтировать в `fly.toml`.
